## 一、测试策略

### 1.1 测试金字塔

本变更是**基础设施与运维**性质，测试重心不在单元测试，而在**端状态验证**：

- **单元/静态**（约 25%）：部署脚本语法检查、GitHub API 响应字段核对
- **集成**（约 45%）：裸库端状态、镜像钩子行为、凭证形态
- **E2E**（约 30%）：真实提交 → 推送 → GitHub 出现同一提交（完整链路）

### 1.2 测试原则

- **看端状态，不看回显** —— 远端命令存在执行两次的环境特性，回显可能是两次中某一次的输出。一切结论以 `rev-parse` / `ls-remote` / API 查询为准
- **幂等必须实测** —— 部署脚本至少跑两次，第二次必须保留数据
- **验证"不做什么"** —— 例如"不重复注册 Deploy Key"、"不静默覆盖远端提交"，这类否定式断言容易被忽略，但正是安全边界所在
- **敏感信息不出现在仓库** —— 私钥、token 不得进入 git 追踪范围
